# Finance v1.2.3｜利用先ルールとカテゴリー管理のUI改善

Finance v1.2.2に上書きする差分パッチ。**OneDriveを正本とする暗号化保存・PDF原本・年別の明細ファイル構造・鍵導出方式は変更なし**。

## 主な変更点

1. **「カテゴリーを管理」からモーダルを開く**。ルール一覧の下の常時展開エリアは撤去した。
2. **カテゴリーを一括編集**。複数の名称・色を編集し、追加・削除したあと、最後の「変更をまとめて保存」1回で `finance/rules/merchants.enc` にアップロードする。1行編集ごとに保存・再描画しない。
3. **一括編集の安全性**。未保存のまま閉じる際は破棄を確認。通信失敗時はモーダルと入力を保持して再試行可能。保存成功後にモーダルを閉じ、一覧とカテゴリー選択肢を更新する。
4. **カテゴリー削除**。一括保存時に削除履歴を暗号化保存し、関連する利用先ルールを「分類しない」にする。元の明細・PDF原本には触れない。
5. **登録済みルールをコンパクト化**。PC幅では1行でルール名・元の名称・カテゴリー・操作ボタンをまとめ、スマホでは必要最小限の2段に表示。
6. **カテゴリー選択の色情報**。フォーム上の選択欄に選択中の色のドットを表示し、選択肢に「食費（橙）」のように色名も記載。OS依存でoptionの文字色が表示されなくても色名で判別できる。
7. **適用プレビュー撤去**。ルール登録フォームの余計な表示を削除。

## 技術メモ

- `src/ui/category-draft.ts` はモーダルの変更前・変更後の差分を検証し、`upserts`と`removeIds`を組み立てる。入力中はOneDriveへ書き込まない。
- `LiveVault.applyCategoryBatch()` はカテゴリーの追加・編集・削除と関連ルールの分類解除を、**1つの暗号化ルールドキュメント更新**としてまとめる。従来のETagおよび3方向自動マージを利用する。ファイルサイズや認証権限は変更しない。
- 旧`upsertCategory()`と`removeCategory()`は既存のテストや内部互換性のため残しているが、画面からは一括APIを使用する。
- 同じ名前のカテゴリーは重複登録不可。新しいカテゴリーは固有IDを持ち、名称を変更しても既存ルールとの対応は不変。
- カテゴリー編集モーダル内の未保存データはブラウザメモリのみ。ページを閉じたりリロードしたりすると未保存の編集は失われる。
- 旧端末のv1.2.1等でルールを保存すると新しいカテゴリーを扱えない可能性があるため、MacとGalaxyのバージョンを揃えて使用すること。

## Macへの適用

```bash
cd ~/Documents/finance || exit 1
unzip -o ~/Downloads/finance-v123-category-modal.zip -d ~/Documents/finance
npm run check
npm run test
npm run verify:cloud
```

終了後にブラウザで `⌘ + Shift + R`。MSAL認証ライブラリが無いという検証メッセージの場合は `npm install && npm run build` を実行する。
