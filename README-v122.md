# Finance v1.2.2｜カテゴリーを自由に管理

Finance v1.2.1向けの差分パッチ。12種類の初期カテゴリーを固定選択するだけだった仕様を、**カテゴリー自体を追加・名称変更・色変更・削除できる**仕様に変更する。

## 画面・使い方

1. 左メニュー「利用先ルール」→「カテゴリーを管理」を押す。右側の「カテゴリーを管理する」が表示される（初期状態でも展開済み）。
2. 一覧でカテゴリー名を書き換える、あるいは12色の名前付きパレットから色を選び、その行の「保存」を押す。既存の12カテゴリーも編集・削除可能。
3. 一覧の下の「新しいカテゴリー名」「色」を入力・選択して「カテゴリーを追加」。入力後はルール登録の「カテゴリー」選択肢にも表示される。
4. 「削除」は確認ダイアログ付き。そのカテゴリーを参照していた**利用先ルールだけを「分類しない」に変更**する。カード会社の元利用先、PDF原本、取引金額、年別明細JSONは変更しない。

## 永続化・互換性

- OneDriveの保存先は従来どおり `finance/rules/merchants.enc`。解析済み明細、PDF原本、`finance/index.enc`は変更しない。
- AES-256-GCM暗号化、鍵、AAD、および外側の暗号化形式は維持。内部の `finance-merchant-rules-v1` JSONに**任意** `categoryDefinitions` と `deletedCategories` を追加。
- v1.2.1の既存12カテゴリーと `categoryColors` は自動継承。変更されるまでは従来どおり表示し、旧データの再アップロードを要求しない。
- カテゴリーIDは名称変更後も不変。新規作成は `cat-<UUID>`。12色のパレット定義のみ固定。
- OneDriveのETag付き3方向マージにカテゴリーのID単位・名前/色フィールド単位の統合を追加。カテゴリー削除の情報も保持して、古い端末から勝手に復活するのを防止。削除と更新が同時に発生した場合、独立編集のデータ保全を優先し、結果は暗号化競合履歴に残す。
- **古いv1.2.1クライアントで新しいカテゴリー入りのルールファイルを再保存すると、新フィールドが失われる可能性がある。Mac・Galaxyを両方v1.2.2に更新してから運用すること。**
- カテゴリーの編集・追加はルール表示にすぐ反映されるが、取引ごとの個別カテゴリー上書きは未実装。
- ブラウザ上の編集内容はOneDriveの保存成功が返るまでは保存済み扱いにしない。通信失敗時はメッセージを表示。

## Macへの適用

```bash
cd ~/Documents/finance || exit 1
unzip -o ~/Downloads/finance-v122-custom-categories.zip -d ~/Documents/finance
npm run check
npm run test
npm run verify:cloud
```

`verify:cloud` は Mac 上で MSAL がビルドされている必要がある。必要なら `npm install && npm run build` を先に実行する。完了したら `⌘ + Shift + R` で更新。

## 検証

- TypeScriptの型チェック、既存のテスト＋新規カテゴリーCRUD/競合/暗号化互換性テスト。
- ChromiumでPC幅1440px、スマホ幅390pxにて、カテゴリー追加→名称変更→色変更→利用先ルール割り当て→カテゴリー削除→未分類への変更を確認。
- Microsoft実アカウントによる書き込みは、ユーザー端末での検証が必要。
