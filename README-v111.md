# Finance v1.1.1 | OneDrive通信高速化パッチ

対象: **Finance v1.1.0**。既存のOneDrive `finance/` / `payroll/` フォルダ、暗号化方式・鍵導出・ファイル名・JSONスキーマは変更しません。旧データの移行も不要です。

## 変更点

1. **フォルダIDをメモリ内で使い回す**: Graphの`/me/drive/special/approot`と各階層のフォルダ検索を、同じOneDriveクライアントの起動中は原則1度だけ実行します。同時に同じフォルダを利用する場合も解決処理を共通化します。404などのエラーを恒久的なフォルダ存在情報としてキャッシュしません。
2. **年度別ファイルを最大4件並列取得**: ロック解除や更新確認時、変更がない年は既存のETagに基づくメモリ上の復号結果を使い回します。変更のある年は一覧で得たIDから取得し、余分なパス問い合わせを減らします。
3. **索引の重複読み込みを削減**: 解除時に取得した`index.enc`を引き続き使用し、同じ操作内で重ねて取得しません。
4. **変更なしの年は本文の再取得を省略**: 保存前にGraphの`If-None-Match`でETagを確認し、`304 Not Modified`なら既存の復号済みデータを再利用します。変更があった場合は最新の暗号化データをダウンロード・復号してマージします。
5. **保存直後の再ダウンロードを削減**: アップロード完了応答に有効なIDとETagがある場合は、そのデータに対応する復号済み内容を保持します。GraphがETagを返さない場合は従来どおり読み戻して検証します。次回の更新確認で新しいETagが見つかれば必ず再取得します。
6. **安全性は維持**: AES-256-GCM、PBKDF2、OneDriveへの暗号化データのみの保存、条件付きアップロード・競合時の再マージ、PDF原本の不変保存を維持しています。小容量ファイルでも既存のETag付きアップロードセッションは維持し、根拠の弱い無条件PUTへは変更していません。

## 適用

```bash
cd ~/Documents/finance || exit 1
unzip -o ~/Downloads/finance-v111-speed-patch.zip -d ~/Documents/finance
npm run check
npm run test
npm run verify:cloud
```

ブラウザで `⌘ + Shift + R` を実行してください。ZIPにはビルド済み`dist`も含み、`node_modules`や`dist/vendor`は上書きしません。

## 確認の手順

1. MacでOneDriveの保管庫を解除し、従来と同じ明細件数・請求額であることを確認。
2. 既存の明細を1件編集して保存し、Macで再読み込みして反映を確認。
3. Galaxyでも同じOneDriveを開いて更新反映を確認。
4. 接続を切った状態で保存すると保存失敗として扱われることを確認し、再接続してから再試行。

**性能の数値は実際のGraph通信環境・年度数・回線・端末に依存します。** 自動テストは模擬Graph APIのリクエスト回数と並列性を検証していますが、実アカウントでの所要時間は未計測です。なお、初回の旧形式データ移行時にはPDF原本の照合や複数ファイルの転送が必要なので通常操作より時間がかかる場合があります。
