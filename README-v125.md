# Finance v1.2.5 | OneDrive保管庫のパスフレーズ変更

## 使い方

1. OneDriveへ接続し、Finance保管庫を解除する。
2. OneDrive接続画面の「暗号化パスフレーズ → パスフレーズを変更する」を開く。
3. 現在のパスフレーズ、新パスフレーズ、確認を入力し、変更を実行する。
4. 完了後は1Password等の保存内容を更新し、別端末もv1.2.5以降を使用して新しいパスフレーズで解除する。

12文字以上が必要。変更中はページを閉じたり、別の端末から編集しない。

## データの保護方法

- Finance本体にパスフレーズは保存しない。現在のパスフレーズを暗号化索引で照合する。
- 新しいランダムソルトと鍵で、現行の年度別明細、参照中のPDF原本、利用先ルール、資産設定を再暗号化する。
- 再暗号化データは `finance/versions/<世代UUID>/` 下に別保存し、復号して元のデータと突き合わせる。
- すべてのコピー・検証が成功し、かつ元のファイルが更新されていなければ、**最後に** `finance/index.enc` をETag条件付きで差し替える。
- Graphへの保存途中で失敗しても、既存の索引を切り替えない。失敗時の中途半端な新世代ファイルは参照されない。
- 旧世代ファイルは自動削除せず、復旧用として保持する。**古いファイルやOneDriveのファイル履歴は旧パスフレーズで読める場合がある**。今回の操作は、過去のコピーを秘密鍵ごと抹消するものではない。
- 新しい世代に切り替わると、以前のタブ保存鍵・旧画面からの更新は拒否する。改めて新パスフレーズで解除する。
- Payrollフォルダ、旧IndexedDB、従来のバックアップファイルは変更しない。

## 既知の制約

- 実際のMicrosoftアカウントによるGraph上のフル再暗号化はこの環境では未検証。Macで一度実施して、明細・PDF・ルール・資産設定を確認する。
- 保存対象が多いほどOneDrive通信と容量を使用する。途中で閉じると保存先に未採用の新世代フォルダが残る場合がある。
- 旧世代データの整理・削除UIは未搭載。誤削除による復旧不能を防ぐため、自動削除しない。
- 変更中の他端末からの書込みは避ける（競合更新が検知された場合は索引を切り替えず失敗とする）。

## 検証

`npm run check`、`npm run test`、`npm run verify:cloud` を実行。実Graph通信と、パスフレーズ変更後の別端末操作はユーザー環境での確認が必要。
