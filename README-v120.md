# Finance v1.2.0：利用先ルール管理

Finance v1.1.3へ重ねる差分パッチです。**カード会社の元の利用先は保持**し、表示する名称だけをルールで統一します。年別解析データ・暗号化索引・PDF原本・既存のOneDrive保存先は変更しません。

## 新機能

- サイドバー「利用先ルール」を追加。完全一致・前方一致・部分一致、全カードまたは指定カードのみ、優先順位、有効/無効、編集、削除に対応。
- 「明細の管理」の各利用先に「ルール化」を追加。元の利用先名を入力した新規登録フォームを開きます。
- ルールの適用時は、過去に保存した明細や今後の取込プレビューに表示時だけ反映。明細ファイルを一括書換えせず、PDF原本と元の利用先表記も保持します。
- 明細管理で利用先の表示名を直接編集した場合は `merchantOverride` に個別指定として保存。表示名は **個別指定 ＞ 共通ルール ＞ 元表記** の順。
- 重複取込の判定はカード会社の元表記（`merchant`）に基づくため、ルール変更では重複判定の基準が変わりません。
- ルール登録画面に一致件数と変換プレビューを表示。元表記の比較では NFKC正規化・英字の大小・連続空白を吸収しますが、元データは変更しません。

## OneDrive保存構造

```text
OneDrive / Apps / <共通アプリ名> /
├── finance/
│   ├── index.enc
│   ├── statements/YYYY.enc
│   ├── originals/YYYY/MM/UUID.enc
│   └── rules/
│       └── merchants.enc     # 今回追加。AES-256-GCMで独立暗号化
└── payroll/                 # 既存の予約領域。変更なし
```

- `merchants.enc`は新しいルールを初めて保存するまで作成されません。旧ユーザーは既存のパスフレーズでそのままロック解除できます。
- Finance既存の鍵（PBKDF2-SHA256、310,000回、索引ソルト）を再利用しますが、暗号化AADは `Finance OneDrive merchant rules v1` として分離。
- ルールを保存・編集・無効化・削除するたびに、暗号化したファイルだけをOneDriveへ更新。変更成功の応答後に「保存済み」と表示します。
- ETagによる条件付き更新と3方向マージで、同時に異なるルールを追加した場合は統合。**同じフィールドの競合は保存操作側を採用し、他方の値を暗号化された競合履歴に残します。** 削除と編集が競合する場合は変更内容を優先して履歴を残します。
- OneDriveへの通信に失敗した場合、ルール編集内容はフォームに保持。既存のクラウドルールは上書きしません。
- 別端末側にはアプリ起動・手動更新・ウィンドウ再フォーカス時のクラウド更新確認で新しいルールが反映されます。

## 既存データとの互換性

- **OneDriveファイルの移行は不要**。今ある`finance/index.enc`・年度別ファイルの暗号化形式はそのまま。
- 既存の`ImportRow.merchant`は元表記として扱い、表示上の個別修正のみ新しい`merchantOverride`を使用。過去にv1.1.3以前の編集で元表記そのものを上書き済みの場合、その書換前の文字列は復元されません。
- IndexedDBへの新規保存は引き続き行いません（旧データの明示的な移行機能だけ存続）。
- ルールが壊れて復号できない場合は、空のルールファイルで上書きせず、保管庫の解除を停止します。

## 適用

```bash
cd ~/Documents/finance || exit 1
unzip -o ~/Downloads/finance-v120-merchant-rules.zip -d ~/Documents/finance
npm run check
npm run test
npm run verify:cloud
```

成功したらFinanceを `⌘ + Shift + R` で強制再読み込みしてください。MSALの認証ライブラリ等は既存のものを利用するため再登録不要です。
