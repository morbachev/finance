# Finance v1.0.0 | OneDriveを正式な保存先に変更

v0.9.4からの移行パッチ。既存のカード解析、照合、一括取込、明細管理UIは維持し、**通常の保存先をIndexedDBからOneDriveに変更**しました。

## 動作モデル

- カード明細と取引データはアプリ専用領域の `finance-v1-vault.enc` にAES-256-GCMで暗号化して保存します。PBKDF2-SHA256（310,000回）でパスフレーズから鍵を導出。パスフレーズと鍵はブラウザのタブメモリにのみ存在し、OneDriveへ送りません。
- PDF原本は個別の暗号化ファイルとしてアプリ専用領域の `finance-v1-originals/<UUID>.enc` に保存。`vault.enc`内には原本のUUID参照のみ含まれます。
- 解析/編集/削除でクラウドへ直接保存。保存済み明細の編集は入力確定後450ms程度で自動保存し、手動の「OneDriveに保存」ボタンでも再試行できます。新しい取り込み明細は従来どおり「明細を一括取り込む」で確定します。
- `vault.enc`はETag条件付きアップロードセッションで書き込みます。競合した場合は最新の暗号化ファイルを取得・復号し、レコードID/行ID/項目ごとに3方向マージして最大5回再試行します。同一項目を両者が変更した場合は保存操作側を採用し、競合した別の値を**暗号化された保管庫内**の履歴に残します。削除と編集の衝突では編集を維持します。
- ロック解除後、他端末の保存内容を確認するにはOneDrive接続画面の「最新データを取得」か、タブに戻ってフォーカスする操作を使います。未保存の編集がある場合の再読み込みは停止します。
- 通信失敗時には保存成功扱いにせず、画面上の未保存状態を維持します。**ブラウザを閉じると未保存の編集は失われるため、保存失敗時は閉じないで再試行**してください。
- 通常操作でIndexedDBは読み書きしません。旧IndexedDBへは「旧IndexedDBからOneDriveへ移行」を押した場合にのみアクセスします。旧データは移行完了後も自動削除しません。
- 0.9.4の`finance-vault-*.enc.json`のバックアップは改変・削除しません。新しいライブ保管庫とは別のファイルとして残ります。

## Macへの適用

既存のv0.9.4で暗号化バックアップを書き出して保管してから適用することを推奨します。

```bash
cd ~/Documents/finance || exit 1
unzip -o ~/Downloads/finance-v100-onedrive-primary.zip -d ~/Documents/finance
npm install
npm run check
npm run test
npm run verify:cloud
```

ローカルで既にPythonサーバーが起動していれば`http://localhost:5173/`を強制再読み込み。停止中は`python3 -m http.server 5173 --directory dist`。

**注意：** Microsoft Entraのアプリ登録に `http://localhost:5173/` とGitHub Pagesの公開URL（SPA）の両方を登録し、Files.ReadWrite.AppFolderを委任アクセス許可として付与する必要があります。

## 旧IndexedDBデータの移行

1. 以前のデータを保存していた**同じURLと同じブラウザプロファイル**でv1.0.0を開きます。別のサイトURLでは旧IndexedDBが見えません。
2. Microsoftアカウントへ接続。OneDriveに新しい保管庫がなければ「新規作成」のモーダルが出ます。旧パスフレーズを使いたい場合は一度キャンセルして移行操作へ進んでも構いません。
3. OneDrive接続→STEP04→**旧IndexedDBからOneDriveへ移行**を押します。旧ブラウザ保存に使用していたパスフレーズを入力します。OneDrive側がロック中なら、先にクラウド保管庫を解除します。
4. 解析明細とPDF原本を順次暗号化してOneDriveへ移し、最後に解析データの参照ファイルを保存します。旧データは削除しません。途中失敗した場合も、同じ操作で再試行できます。クラウドにある同一の保存IDは上書きしません。
5. 一覧件数・カード別請求額を確認してからGalaxy側で同じMicrosoftアカウントにログインし、パスフレーズで復号します。

## 制約と注意

- **本パッチではOneDriveへの実機保存、複数端末での同時編集の本番動作はまだ確認していません。** 型チェックと模擬OneDrive APIの自動テスト、デスクトップ/スマホUIのブラウザテストまで検証済みです。最初は少量の明細で操作してください。
- 現在の方式は単一の暗号化インデックスを用い、Microsoft GraphのETag更新を条件として自動マージします。OneDrive個人用アカウントでのアップロードセッションの実動作を確認してから、大規模な本番データを移行するのが安全です。
- 同じ明細・同じ請求月を**別のIDとして両端末で同時追加**した場合、データを勝手に捨てず両方を残します。画面で重複警告が表示されることがあります。
- PDF原本は追加ごとに暗号化して保存します。明細を削除しても原本は自動物理削除せず、暗号化オブジェクトが残ることがあります（誤削除防止）。
- Google Chromeのオフライン時に閲覧できる機能はありません。OneDriveが利用できない場合は明細の取得・保存ができません。
- ブラウザに残るのはテーマと公開Client ID、Microsoft認証ライブラリのセッション情報。暗号化明細・PDF・パスフレーズはブラウザ永続ストレージに保存しません。
- 過去のv0.9.4暗号化スナップショットを新ライブ保管庫へ直接インポートするUIは未実装です。移行は旧ブラウザのIndexedDBから行います。
- 同じ項目の変更競合に関する暗号化監査履歴は保存されますが、ユーザー向けの履歴閲覧UIや独立した世代別自動バックアップは今後の課題です。

## ファイル構成（OneDriveアプリ専用領域内）

```text
Apps/<registered Microsoft application>/
  finance-v1-vault.enc                    # AES-GCM暗号化された明細とメタ情報
  finance-v1-originals/                  # AES-GCM暗号化したPDF原本
    <UUID>.enc
  finance-vault-*.enc.json                # v0.9.4の過去のスナップショット。変更なし
  finance-v09-connectivity.enc.json      # v0.9.xテストファイル。変更なし
```
