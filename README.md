# Finance v1.6.13

カード明細・口座残高・入出金・資産形成をまとめて管理する、個人向けのブラウザアプリです。HTML / CSS / TypeScriptで構成し、明細PDFと金融データはブラウザで処理します。永続データの保存先には、Microsoft OneDriveの暗号化保管庫を使用します。

## v1.6.13 接続表示の整理
- OneDrive接続中は進行状況だけを表示。不要な補足文を削除。
- 12秒を超えた場合も簡潔な状態表示にする。
- 設定画面の接続状態から重複するサービス名を削除。
- 起動失敗時の復旧操作は残し、冗長な説明文を削除。

## v1.6.12 保存結果未確認の保護・ファビコン

- **利用先ルール・カテゴリー／資産設定**：Microsoft Graphへアップロード後、ETagが返らず照合用の再取得も失敗した場合は「保存失敗」と断定せず、「保存結果未確認」として扱います。Graphからの応答自体が通信途絶で失われた場合も同様です。
- 結果未確認になった同種データの再保存を一時停止します。設定の「最新データを取得」でOneDriveのデータを正常に読み込めた後に解除します。取得が失敗した場合は解除しません。
- 確定的なGraph拒否（例：アクセス拒否）は従来のエラーとして区別。ETagなしでも内容が一致した読み戻しは正常な保存として確定します。
- ルール・カテゴリー・口座管理画面で、未確認の結果を「保存失敗」と誤表示しないよう改善しました。保存形式・暗号化方式・既存のOneDriveデータは変更しません。
- ヘッダーの紺色の「F」と緑色のドットを利用した、**透明背景のSVG / ICOファビコン**を追加しました。ヘッダーの見た目は変更していません。

## v1.6.11 起動中の操作不能対策

- OneDrive自動接続では認証失敗時に `window.confirm()` やMicrosoftログインへの自動遷移を行わず、設定画面で手動再接続できるようにしました。
- 設定を含むナビゲーションを初期化の最初に登録し、途中の例外による操作不能を軽減しました。
- 起動用JavaScriptが読み込めない・初期化に失敗した場合は、独立した復旧パネルから設定表示・安全な起動診断のコピー・再読み込みができます。診断には認証情報・パスフレーズ・個人データを含めません。
- OneDrive接続が12秒以上かかる場合は待機メッセージを表示。Microsoft GraphのGET要求と署名付きGETのレスポンス待ちに30秒の中断期限を設けました。書込みは結果不明を招くため、自動中断しません。
- ブラウザの実際のフリーズ原因はConsoleなどの実行時情報がないと確定できません。復旧パネルの追加は再発時の調査性を高めるためのものです。

## v1.6.10 OneDriveの暗号化索引の取得を修復

- Microsoft個人用OneDriveが返す `https://my.microsoftpersonalcontent.com` のダウンロードURLをCSPの `connect-src` に追加しました。2026年11月18日の実機Consoleログにあった「Content Security Policy によって接続が遮断された」問題を解消する変更です。
- CSPのその他の制限、認証方式、暗号化方式、保存先、既存のOneDriveデータには変更していません。
- 既存の保管庫を新規作成しないでください。修正版をブラウザで再読み込み後、接続確認と既存パスフレーズによる解除をお試しください。
- 実際のOneDriveへ接続する実機テストは未実施です。次に異なるMicrosoft配信先やCORSエラーが現れた場合は、エラーメッセージとドメイン名だけを共有してください。URL内の `tempauth` などの署名付きパラメータは共有しないでください。

## v1.6.9 データ競合・未保存保護

- **カード明細と分類ルールの同時編集**：同一行・同一フィールドが別端末でも編集された場合は、変更内容を比較して確認するまで上書きしません。無関係の行・フィールドは自動統合します。
- **資産の競合確認**：入出金名・日付・金額と端末側／OneDrive側の値を表示します。給与自動取得パスフレーズは画面に表示しません。
- **未保存フォームの保護**：みずほ送金予測とカード引落口座の変更状態を別々に保持し、ページの再読込やロック時の未保存警告に含めます。
- **保存結果の不確実性**：OneDriveで書込み完了した後の再取得失敗は警告として扱い、複数ファイルの部分更新などで結果が不明な場合は「結果を確認できない」と区別します。

## 主な機能

- **明細インポート**：カード会社のPDFやWeb明細を解析し、確認してからOneDriveに保存。PDF原本も暗号化して保管します。
- **明細管理**：年月別の明細検索、利用日・利用先・金額・補足などの確認と編集、原本PDFの取得。原本のダウンロード名は `YYYYMM_カード種別_明細.pdf` 形式です。
- **ルール・カテゴリー**：複数の利用先表記に共通の表示名・カテゴリーを付与。完全一致・前方一致・部分一致に対応します。
- **月別サマリー**：カード請求、定期・単発の入出金、Payrollの給与実績・見込みを集計。楽天銀行の残高推移と、引落日ごとの残高不足も確認できます。
- **口座管理**：楽天銀行・みずほ銀行・現金貯金口座・NISAの残高履歴、定期入出金、単発の入金・支出・振替・現金引出を管理します。
- **カード引落口座・みずほ送金予測**：カードごとの引落口座を指定。楽天銀行からみずほ銀行へカード代金を送金する予定を、請求額に基づき試算します。実際の送金は行いません。
- **資産予測**：現金貯金・NISA・合計の将来推移を表示。目標年齢・想定年利を変更し、積立額を変えた場合の差も試算できます。
- **Payroll連携**：別アプリPayrollの解析済み給与情報を読み込みます。Financeが給与明細PDFを直接解析する仕組みではありません。

予測や見込みは、登録した残高・予定・給与情報に基づく参考値です。銀行の実際の入出金を自動照会する機能ではありません。

## ローカルでの起動とテスト

Node.jsとnpmが必要です。プロジェクトルートで実行します。

```bash
npm ci
npm run check
npm run test
npm run verify:cloud
python3 -m http.server 5173 --directory dist
```

ブラウザで `http://localhost:5173/` を開きます。サーバーの終了は `Ctrl+C` です。`npm run test` はビルドも実行します。

## OneDriveの接続

「設定」からMicrosoftアカウントへ接続し、暗号化保管庫を作成するか既存の保管庫を解除します。Microsoft Entraのアプリ登録には、利用するサイトURLをSPAのリダイレクトURIとして登録し、必要なMicrosoft Graph権限を設定してください。ローカルでは `http://localhost:5173/` を使います。

- 金融データの正本はOneDriveにあります。`src/cloud/` に暗号化・同期・競合解決の実装があります。
- PDF原本、明細、ルール、口座設定は、それぞれ暗号化されたファイルとして保管します。
- 同じ保管庫を別端末から使う場合は、接続先とパスフレーズを一致させます。
- 旧ブラウザ保存データの移行機能は、設定の詳細操作から利用できます。

## 公開・コミット時の注意

このリポジトリはアプリの**ソースと静的配信物**を管理します。PDF原本、実際のカード明細、給与明細、銀行残高データ、認証トークン、パスフレーズ、復号鍵はGitに追加しないでください。

ビルド・テスト後は、`git diff --cached --check` とステージ対象の内容を確認してからコミットしてください。`local-data/`、`private-data/`、`.env`、PDF/CSVなどは `.gitignore` で除外します。

過去バージョンの技術的な変更記録は、Gitの履歴と既存の `README-v*.md` に保存されています。

## 安全性（v1.6.7）

保存済みのカード明細を削除する際は、明細の検算状態に関係なく確認が必要です。暗号化されたPDF原本は、明細削除後もOneDriveに保持されます。

資産・入出金の同じ項目を別端末で同時に変更すると、保存時にどちらを優先するか確認します。キャンセルすると保存せずOneDrive上の値を保護します。異なる項目は従来どおり統合されます。

HTMLにはCSPを設定し、テーマ初期化スクリプトは外部ファイル化しました。`npm run build` は `dist/` を一度削除し、古い生成物が公開されないように再生成します。
