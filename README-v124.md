# Finance v1.2.4 | 資産残高と定期入出金の設定

## 追加した画面

左メニューの「資産・定期入出金」から開きます。OneDrive保管庫の解除が必要です。

1. **口座残高**：楽天銀行、現金貯金専用口座、NISA口座のそれぞれに、残高（0円以上の整数）と確認日時を登録できます。確認日時は端末の現在時刻を入力欄の初期値とし、必要なら変更可能です。「現在日時」で再設定できます。残高は上書きしない履歴方式です。訂正時は誤った履歴を削除して再登録できます。最新残高は登録した順番ではなく**確認日時が最も新しい履歴**を採用します。
2. **定期入出金**：名称、金額（正の整数円）、支出・収入・口座間振替、口座、毎月・毎年・毎週、日付、開始日・終了日、カテゴリー、有効／停止を設定できます。登録済み設定は編集・削除できます。毎月31日等の短い月の処理・末日指定は将来の予測用です。カテゴリーは支出だけの表示メタデータです。
3. **口座間振替**：楽天銀行から現金貯金専用口座への積立などは「支出」ではなく「振替」として登録できます。送金側と受取側を明示して、次段階の残高計算・二重計上防止につなげます。

## 今回の範囲と保留

- **今回は設定の保存と履歴管理のみ**。既存のカード明細との自動照合、口座残高の自動加減、NISAのカード積立額自動取込、Payroll給与データ連携、月別・年別サマリーおよび推移グラフは実装していません。
- ユーザーが銀行明細PDFを取り込む機能は追加していません。
- みずほ銀行への不定額の移動・カード引落先の紐付けも今後の検討対象です。
- NISA口座に入力する金額は手動確認した評価額です。積立額と運用損益は自動計算しません。

## OneDrive保存と互換性

- 新設ファイルは **`finance/settings/assets.enc`**。既存の`finance/index.enc`、`finance/statements/YYYY.enc`、`finance/originals/`、`finance/rules/merchants.enc`およびPayroll名前空間は変更しません。
- AES-256-GCM（既存のPBKDF2鍵・ソルトを再利用、資産設定専用の追加認証データ）、独立したJSONスキーマ`finance-assets-v1`。パスフレーズの平文保存なし。ブラウザのIndexedDBへ通常保存しません。
- GraphのETag条件付き更新、3方向マージ、削除トゥームストーン、競合監査履歴を使用します。保存失敗時は編集フォームの入力を残し、成功扱いにしません。
- 既存v1.2.3の保管庫では設定ファイルがない状態を空データとして扱い、最初の登録でのみ作成します。
- **重要**：資産設定を登録した後、v1.2.3以下の旧アプリを別端末で使い続けると新設定が表示されません。MacとGalaxyの両方を同じバージョンに更新してください。

## Macへの適用

```bash
cd ~/Documents/finance || exit 1
unzip -o ~/Downloads/finance-v124-assets-settings-patch.zip -d ~/Documents/finance
npm run check
npm run test
npm run verify:cloud
```

生成済み`dist/`もパッチに含めています。GitHub Pagesは公開用`dist/`を含めて更新してください。公開後はブラウザで強制再読み込み（Macは⌘+Shift+R）。

## 確認ポイント

1. アプリの保管庫を解除後、「資産・定期入出金」へ移動。
2. 3つの口座で順番に残高を保存し、画面を再読み込み・再復号して値と履歴が残ることを確認。
3. 支出・収入・振替を各1件登録し、編集・削除して動作を確認。
4. Macで保存した値をGalaxyで「最新データを取得」して確認。
5. 一時的なオフライン状態で保存し、失敗メッセージが表示され入力が残ることを確認。再接続後に保存できることを確認。

ローカルの自動テストは実Microsoftアカウントとの通信を代替しません。Microsoft Graph通信は実アカウントで検証してください。
